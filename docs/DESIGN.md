# Design and implementation record

Approved goal: no-root Android prototype returning from shake-triggered and clicked cross-app ad redirects, built after reviewing existing projects.

Chosen reuse: MIT Android-Touch-Helper service shell and package discovery. New pure Java state machine, foreground-verifying controller, native settings UI and controlled test apps. Same-package internal advertising and universal page restoration are explicitly outside first-version guarantees.

Protection defaults: 10-second window; choices 5/10/20/30; maximum 3 actions per recovery and 6 per source session; 120ms stable-source confirmation. The window limits only when a cross-app jump is detected; a recovery that started may run for up to 6 s. No action is sent the moment a jump is seen: the first action waits until the foreground page (package + Activity) has stayed the same for 400ms, or 1500ms have passed. Each retry waits 700ms after Back (900ms after relaunch) and for the page to settle again. With the optional relaunch, the cross-app order is Back → relaunch source → Back, because Back cannot leave a target that opened in its own task, and relaunching cannot leave a target that opened inside the source task. Without relaunch, Back is sent three times. A click never confers permission.

Same-app ad pages (2026-10-29): `AdPageClassifier` recognises ad SDK landing-page Activity classes plus user rules (an exact name, or a prefix ending in `*`). Inside a protected source app, such a page is closed with Back at any time, not only inside the window, and never by relaunch. Reward and full-screen video Activities are excluded on purpose. The built-in class names are not yet confirmed on a Xiaomi device. The engine never acts on an unknown Activity in the same app: callers must pass null after an action until a fresh class is reported, or a stale ad class could trigger an extra Back. `GuardController` records the class from each window-state event only when `PackageManager` confirms the package declares it as an Activity. It drops the source and target entries before every action and clears all entries on cancel. Extra rules are stored in the `ad_rules` preference, which has no settings UI yet. User-configured pair allowance and pause take precedence. Window events are sampled after 40ms; recoveries recheck at 100ms intervals. These are prototype parameters, not measured latency claims.

Read permission: Android requires `canRetrieveWindowContent` for the window/root metadata used by verification. The code only reads package names, window types, active/focused flags and the class name carried by window-state events, not text, fields or screenshots. System UI, discovered Home/IME/settings/dialer packages, lock screen and unknown foreground cause cancellation. A source app's input-method or other system interaction can therefore cause a missed interception; this favors stopping over pressing Back on an unrelated interface.

Implementation sequence: executable failing core-test setup → state machine → 26 passing behavior cases → Android adapter/UI → two fixture apps → build, static analysis and review → signed debug distribution. Work directory was unexpectedly removed by the environment during development; source was restored and all core cases rerun, followed by a saved source checkpoint. Subsequent validation is against the restored source.

Public repository requested by the user: `anti-shake-ads`. No personal conversation history, signing keys, credentials or local environment paths belong in the repository.
