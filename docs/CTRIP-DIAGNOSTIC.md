# 0.2.2-diagnostic：携程应用内网页诊断

本版只增加观察和导出，不自动关闭同应用内广告，也未修复跨应用返回失败。现有跨应用策略保持不变。未经用户针对具体发行版授权，禁止发布 Release。

## 手机操作

1. 安装诊断 APK。若提示签名不兼容，停止安装并核对旧 APK 的签名；不要为覆盖安装擅自卸载或清数据。
2. 确认无障碍服务已连接。打开反摇一摇广告 → 设置 → 携程诊断（仅记录）。
3. 点“开始新一轮（120 秒）”。从桌面打开携程，手动点击开屏广告，停留几秒。
4. 回到本应用 → 设置 → 携程诊断 → 停止并导出 JSON，选择文件保存位置。
5. 正常酒店详情/活动页另开一轮，并单独导出。两轮各补一张截图或说明，用于判断容器是否复用。

诊断不修改保护开关。无障碍已连接时，即使跨应用保护关闭，也记录携程窗口元数据；只有已选携程、保护有效且观察到启动/首页后处于保护时长内，才额外标记 candidate=true。测试正常网页时同样需要记录实际保护状态。候选计数是事件次数，不是广告次数。

## 数据与限制

- 默认不开启；两分钟后停止；最多保留 800 条，溢出淘汰旧记录并报告 droppedEvents。窗口包名缺失仅计数，不猜测包名。
- **记录仅在内存中，进程死亡会丢失。每轮完成立即导出，开始新一轮会清空旧记录。** 不联网、不自动上传。
- 记录携程的事件源类名、windowId、事件源节点类名/resource ID、事件时间及保护状态；不读取页面文字、描述、URL 或截图，不遍历完整节点树。
- eventClass 可能是 View 类而非 Activity。未看到 MktH5ContainerV2 不等于未出现广告。
- 候选特征只来自携程 8.78.6 真机的单次样本，未验证正常页面负样本，不作为通用广告判断。
- 观察到首页只能作为启动上下文的近似证据，不能证明冷启动。重复首页事件不延长窗口，新的开屏事件重新建立上下文。
- elapsedRealtimeMs 用于本进程事件排序；eventUptimeMs 与其时基不同，休眠时不可直接相减；wallTimeMs 用于与校准后的电脑日志对应。
- 额外记录现有携程跨应用返回动作的系统调用结果、引擎尝试数和结束原因；调用返回 true 不是页面恢复成功。
- JSON 不包含全系统日志或真实广告网页地址。请与本地 ADB 日志一并提供，标注手动操作。

## 验证范围

核心候选规则有启动窗口、精确包/类名匹配、开关/勾选限制及时钟倒退测试。Android 仪器测试检查默认关闭、文本排除、其他应用排除、缓冲上限、停止、新轮清空和 JSON 序列化。模拟事件不证明携程真机能提供此类名，也不证明广告返回已解决。
