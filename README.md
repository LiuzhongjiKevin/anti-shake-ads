# Anti-Shake Ads · 反摇一摇广告

一个无需 root 的 Android **跨应用跳转后返回**实验应用。摇一摇广告或误点广告把你带到别的应用时，在保护时间窗内尝试回到来源应用。

> 当前是测试版。它不拦截传感器、不阻止跳转发生、不保证广告页面完全不闪现，也不保证所有应用都能恢复到原页面。它按用户选择的来源和时间窗工作，不是能够自动识别所有广告的分类器。

## 功能

- 选择需要保护的应用，进入后默认保护 10 秒，可改为 5 / 20 / 30 秒。
- 对摇动触发与点击触发一视同仁；点击不会被当作放行理由。
- 为每个来源设置允许跳转的目标应用。
- 最多尝试 3 次系统返回，整个保护会话最多 6 次；返回后不续期。
- 只有确认来源包名重新在前台并稳定一小段时间才记录“已回到原应用”。
- 可选“重新打开来源”兜底，默认关闭，结果单独记录。
- 暂停 60 秒，支持下拉快捷设置磁贴；本地最近 100 条记录可清空。
- 不联网、不上传遥测、不保存截图、网页正文或输入文字。

## 安装和第一次测试

需要 Android 8.0 或更新系统。下载三个测试 APK（均为 debug 签名，供测试使用）：

| APK | 用途 |
| --- | --- |
| [anti-shake-ads-0.1.0-test.apk](downloads/anti-shake-ads-0.1.0-test.apk?raw=1) | 主应用，手机上显示“反摇一摇广告” |
| [fixture-source.apk](downloads/fixture-source.apk?raw=1) | “跳转测试源”，模拟点击、自动和摇动跳转 |
| [fixture-target.apk](downloads/fixture-target.apk?raw=1) | “模拟广告页”，无真实广告、无联网 |

1. 安装主应用，阅读应用内说明并到系统设置开启它的无障碍服务。
2. 打开“开启跳转保护”，在“选择保护应用”中勾选“跳转测试源”。
3. 首次测试可把保护时长设为 30 秒，给自己留出操作时间。
4. **回桌面，再打开跳转测试源**。输入任意文字，关闭键盘，点击“模拟误点”。
5. 检查是否返回、输入是否保留、页面实例编号是否相同。然后再测试“1 秒后打开”和真实摇动。
6. 回到主应用看记录。每轮测试前重新从桌面打开来源，重新开始时间窗。

## 用高德地图验证真实开屏跳转

1. 从[高德地图官网](https://mobile.amap.com/cn/)或设备的正规应用商店安装高德地图，不要安装来源不明的 APK。
2. 打开本项目的主应用，在系统设置启用“反摇一摇广告 · 跳转保护”无障碍服务；返回主应用，打开“开启跳转保护”。
3. 点“2 · 选择保护应用”，搜索“高德地图”或包名 `com.autonavi.minimap`，勾选并保存。初次验证设为 30 秒，确认状态显示“保护已就绪”。
4. 按 Home 回桌面，从桌面图标正常打开高德地图。无需从保护应用进入高德；主应用界面也无需一直停在前台。
5. 若高德这次确实出现开屏广告，在 30 秒内点击广告，观察跳到哪个应用、是否返回高德的**原页面**，再看主应用“查看最近返回记录”中的来源、目标和结果。每轮重新从桌面打开高德；广告不出现时，这一轮无法验证。
6. 测试期间若正常导航、登录或支付被返回，可点“暂停 60 秒”，或为高德配置具体的允许跳转目标。

服务必须在系统无障碍设置中保持启用、主开关保持打开；部分设备可能需要允许后台运行或自启动。当前版本主要识别跨包跳转：如果广告打开的是高德应用内部页面或同一包名内的 WebView，无法通用地自动返回。看到“已回到原应用”仍应核对原页面是否保留；如果日志写“重新打开来源”，说明回到的可能是首页。

系统若提示“受限设置”，按设备提供的正常授权流程，在应用信息页查找“允许受限设置”，再开启无障碍。不同厂商可能还需要允许后台运行或自启动。

测试应用只是辅助验证，不是主应用的依赖。测试结束后可以卸载两个辅助应用。

## 正常登录、支付被返回怎么办？

保护期内系统不能可靠判断一次跳转是否出于你的真实意愿。可以先暂停 60 秒，或在“管理允许跳转的目标”中设置来源→目标允许关系。不要把整个支付应用当作所有来源的永久全局白名单。

## 已知边界

- 同应用内部 WebView、Activity 或页面路由，不依靠包名变化通用识别。
- 原应用被系统杀掉、页面自行关闭或目标改变任务栈时，可能无法恢复原页面。
- 重新打开来源可能回到首页。这与恢复原页面不同。
- Home、系统界面、锁屏或不能确定的前台窗口会停止当前保护链，可能漏拦。
- 分屏、画中画、应用分身、工作资料和特殊厂商窗口需要设备级验证。
- 只针对设定的短时窗口；不是全天候阻止所有跨应用跳转。
- 无障碍服务可能被厂商后台管理停止。设置页会显示服务是否在运行。
- 测试版使用 debug 签名；不同构建机器的 debug 签名可能不同，不能保证覆盖安装。正式发行需使用固定私有签名密钥。

## 构建

用 Android Studio 打开项目根目录，安装 SDK 35 和 Build Tools 35.0.0，使用 JDK 17。

```bash
# Linux / macOS
chmod +x gradlew
./gradlew assembleDebug
bash scripts/test-core.sh
./gradlew lintDebug
```

Windows：

```powershell
.\gradlew.bat assembleDebug
.\gradlew.bat lintDebug
```

纯 Java 核心测试可在 Git Bash / WSL 中执行 `bash scripts/test-core.sh`，或按该脚本里的两条 Java 命令运行。

APK 在各模块 `build/outputs/apk/debug/` 中。详细设备测试步骤见 [docs/TESTING.md](docs/TESTING.md)。实际验证结果见 [docs/VALIDATION.md](docs/VALIDATION.md)。

## 项目结构

- `app/.../core/GuardEngine.java`：不依赖 Android 的保护状态机。
- `GuardController.java`：观察活动窗口、执行有界返回、核实结果。
- `GuardService.java`：无障碍服务生命周期。
- `Prefs.java` / `EventLog.java`：本地设置和有界记录。
- `MainActivity.java`：授权说明、应用选择、允许规则、记录和设置。
- `fixture-source` / `fixture-target`：独立安装的跳转实验应用。
- `tests/`：可直接用 JDK 执行的行为测试。
